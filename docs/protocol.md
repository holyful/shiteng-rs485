# STX-W 关联设备的 RS485 帧协议

本文描述已经观察到的字节和受控操作对照，不是厂商完整规格。
适用范围和未验证项目见 [兼容性](compatibility.md)。所有示例是可独立核验的短帧，
不包含原始家庭日志、照片或设备序列号。

## 串口与角色

已测试链路使用 RS485、9600 波特、8 数据位、无校验、1 停止位（8N1）。
这是本次设备的参数，不是所有湿腾设备的出厂默认值。

原厂面板可在没有主机时主动发送 `0x81`、`0xC4` 和周期性 `0x20` 帧；
接入对应主机后可以观察到反向帧。因此不能因为旧资料使用“从站”一词，
就假定本链路必须由外部 Modbus 主站轮询面板。
已知帧中没有独立识别出的 Modbus 站址字段，`TYPE` 也不是 Modbus 功能码。
其他接口的 Modbus 寄存器表不能直接套用到本协议。

## 帧格式

```text
7E TYPE LEN_H LEN_L PAYLOAD... CRC_H CRC_L 0D 0A
```

设载荷长度为 `N`，则长度字段 `L = N + 6`，完整帧长度为 `N + 8 = L + 2`。
文档中的字节下标从 0 开始；Lua 数组下标从 1 开始。

| 字节位置 | 内容 | 规则 |
| --- | --- | --- |
| 0 | `7E` | 帧起始字节 |
| 1 | `TYPE` | 一字节类型，未知类型仍可作为完整帧解码 |
| 2..3 | `LEN_H LEN_L` | 大端无符号长度；包含起始字节、类型、长度、载荷和 CRC，不包含末尾 CRLF |
| 4..`N+3` | 载荷 | 由帧类型解释；可包含 `7E`、`0D 0A` 等字节 |
| `N+4`..`N+5` | CRC | 高字节在前 |
| `N+6`..`N+7` | `0D 0A` | 固定结束字节 |

例如，下面的 `LEN=0x000A` 表示 10 字节，不含最后两个字节：

```text
7E 81 00 0A 41 20 14 00 5C D5 0D 0A
            └──载荷──┘ └CRC┘
```

不要用 USB、TCP 的一次 `read()` 或换行符作为帧边界。解码器按声明长度取完整帧，
同时验证 CRC 和结束字节；`PAYLOAD` 内的换行不具有分帧意义。

## CRC

计算参数是 CRC-16/MODBUS：初值 `0xFFFF`，反射多项式 `0xA001`，最终异或 `0`。
覆盖范围从 `7E` 开始，到载荷最后一个字节结束；不覆盖 CRC 本身和 `0D 0A`。
计算结果在本协议中按**高字节、低字节**发送，这一点与标准 Modbus RTU 不同。

```python
crc = 0xFFFF
for byte in header_and_payload:
    crc ^= byte
    for _ in range(8):
        crc = (crc >> 1) ^ (0xA001 if crc & 1 else 0)
wire_crc = bytes((crc >> 8, crc & 0xFF))
```

`7E 81 00 0A 41 20 14 00` 的 CRC 数值为 `0x5CD5`，线上两字节为 `5C D5`。
CRC 有效证明字节与算法一致，不证明载荷解释正确，也不证明设备执行了操作。

## 整体控制：`0x81`

已标注的面板操作使用四字节载荷 `p0 p1 p2 p3`。这是一组完整目标状态，
不是“只改某一字段”的独立线上命令。

| 已观察位或字节 | 受控对照支持的含义 | 边界 |
| --- | --- | --- |
| `p0 & 0x80` | 目标电源：0 关，1 开 | 由相同基态的开关对照支持 |
| `p0 & 0x40` | 目标控制：0 手动，1 自动 | 已有手动及回切自动的面板标注 |
| `p0 & 0x03` | 0 新风，1 内循环，2 内除湿，3 新风除湿 | 已标注一轮模式切换 |
| `p1 & 0x60` | `0x20` 低，`0x40` 中，`0x60` 高 | 最初在开机、手动、内循环基态下对照；不证明整个风速字段只有两位 |
| `p1 & 0x04` | 最终新风/新风除湿样本置位，内循环/内除湿清零 | 相关位，物理含义未知；不能直接称为风阀或电机 |
| `p2 p3` | 已标注控制样本为 `14 00` | 不透明字节，不给它们命名为温度或其他物理量 |
| 其余位 | 未识别 | 修改状态时保留，不默认清零 |

部分原厂面板短帧如下。这里的“开机”“自动”等是面板显示及操作标签，
不是单凭这些发送帧就确认主机的机械状态。

| 操作标签 / 基态 | 完整帧 |
| --- | --- |
| 关机、自动、低档、内循环 | `7E 81 00 0A 41 20 14 00 5C D5 0D 0A` |
| 开机、自动、低档、内循环 | `7E 81 00 0A C1 20 14 00 9C FC 0D 0A` |
| 开机、手动、低档、内循环 | `7E 81 00 0A 81 20 14 00 5C E9 0D 0A` |
| 开机、手动、中档、内循环 | `7E 81 00 0A 81 40 14 00 42 E9 0D 0A` |
| 开机、手动、高档、内循环 | `7E 81 00 0A 81 60 14 00 88 E8 0D 0A` |
| 开机、手动、中档、新风 | `7E 81 00 0A 80 44 14 00 7F A9 0D 0A` |
| 开机、手动、中档、新风除湿 | `7E 81 00 0A 83 44 14 00 3B A9 0D 0A` |

模式切换存在中间状态。例如一次新风除湿切换观察到
`83 20 14 00` → `83 24 14 00` → `83 44 14 00`，相邻变化约间隔 0.31 秒。
回到内循环时出现 `81 44 14 00` → `81 40 14 00`。
第一次改变的帧不一定是最终稳定状态。

`patch_control` 只修改指定的已观察位，保留其他位和尾字节；指定模式时，
也会根据上述最终样本调整 `p1` 的 `0x04` 位。这是对最终状态的建模，
并未实现原厂所有过渡时序。返回值仍是四字节载荷，需要以类型 `0x81` 编帧。

`make_control` 要求明确提供电源、自动/手动、风速和模式，使用 `14 00` 作为观察到的
尾字节基线，并将其他未指定的不透明位设为零。它适合显式构造完整目标；
若已有可信的当前载荷且希望保留未知位，优先使用 `patch_control`。
由位组合生成的其他状态不自动成为“已经原厂抓包或实机验证”的案例。
风速零、停止档及第四档没有确认，库不提供这些选项。

## 目标湿度：`0xC4`

原厂面板分别设置并保存 55% 和 60% 时，观察到：

```text
55%  7E C4 00 08 00 37 C0 3B 0D 0A
60%  7E C4 00 08 00 3C 07 7A 0D 0A
```

载荷 `00 37` / `00 3C` 与未缩放整数百分比一致。高字节在两个案例中都为零，
不能据此宣称已测试非零高字节的含义。这里只确认了这两个原厂标注值。

`encode_humidity` 接受 **30..90 的严格整数**。该范围是库的应用策略，
不是已证明的协议极限、所有机型的能力范围或逐值实测结论。
布尔值、小数及越界值应拒绝；不能静默截断或钳位。
未建立 `0xC4` 的可靠回复类型、写入确认或断电持久化规则。

## 周期帧：`0x20`

```text
7E 20 00 07 00 FA 05 0D 0A
```

原厂面板约每 3.2 秒发送一次。API 名称 `heartbeat()` 是便于调用的名称，
不是已证明它仅承担心跳的协议定义；它也可能参与状态轮询。
主机连接后有成组反向数据，但轮询与各回复类型的一一关系尚未完整确定。
库函数只返回字节，不启动定时器，也不在连接时自动发送。

原厂部分控制操作出现约六次重复发送；重复帧不算多次独立试验。
这不足以确立通用重试次数、超时或必须复制的重发策略。

## 主机回包和命令结果

主机链路已见 CRC 有效的 `0x01`、`0x69`、`0xA0`、`0xA2`、`0xA8`、
`0xAA`、`0xAB`、`0xAC`、`0xB6`、`0xC8` 等类型。
在某些 `0x81` 发送之后，出现类型改为 `0x01`、四字节载荷相同且重新计算 CRC 的反向帧。
这支持“匹配的协议回包”，但没有识别出事务编号、状态码或通用 ACK 定义。

应用应区分以下结果：

1. 适配器写入成功：字节交给了本地传输层。
2. 匹配回包：观察到方向、类型、载荷和时间关系符合预期的反向帧。
3. 实机效果：独立观察到所请求的运行变化。

第二项不能代替第三项。仅载荷相同也不足以排除转发器回显或历史帧；
应用需要自己的方向记录、时序和会话边界。库不伪造设备 ACK 或机械执行结果。

## 实验性传感器解释

以下只是针对本次链路的候选解释，**默认完整帧解码不会应用它们**。
调用者显式调用 `decode_experimental(frame)` 才启用；返回结果带 `provisional=True`。

| 类型 | 试验解释 | 尚未证明的部分 |
| --- | --- | --- |
| `0xA2`，两字节 | 大端整数温度，单位 ℃；试验实现采用有符号值 | 具体探头位置、负值编码、缩放和跨机型适用性 |
| `0xA8`，两字节 | 大端整数相对湿度，单位 % | 具体探头位置和字段语义 |
| `0xAC`，两字节 | 大端整数 PM2.5，单位 µg/m³ | 实际污染物、单位、缩放和量程 |

值看起来像室温或湿度，不构成字段语义证明。同一串口帧派生出的面板显示、MQTT 和
仪表盘也不是三份独立证据。需要原厂显示、独立测量或准确的型号规格对照。
`0xA0/0xAA/0xAB/0xB6` 等仍保持未知，不把缺失值转换成零，
也不把某个类型直接命名为室外或盘管传感器。

## 解码边界

当前实现把完整帧限制为 512 字节，这是内存和输入校验策略，不是厂商声明的上限。
拆包、粘包和未知有效类型受支持；错误长度、CRC 或结束字节会被拒绝并尝试重新同步。

对于长度合理但尚未完整的候选帧，解码器保留它，不会只因后面又出现 `7E` 就跳过：
后者可能属于合法载荷。调用者在确认断连、丢字节或其他流中断后应显式 `reset()`，
并分别管理 RX/TX 解码器。普通短暂 `read()` 超时不能自动证明数据流已经中断。
无效字节不是解码输出的一部分；需要审计时，调用者应另存有界原始字节记录和方向信息。
