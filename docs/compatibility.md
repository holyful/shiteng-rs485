# 兼容性和证据等级

## 当前范围

| 对象 | 已有证据 | 不能由此推出 |
| --- | --- | --- |
| 原厂 STX-W 面板 | 9600 8N1；独立供电时的原厂发送帧；电源、手动/自动、三档风速、四种模式、55%/60% 目标湿度的标注对照 | 所有 STX-W 批次和固件完全相同 |
| 与该面板配套的一台湿腾主机 | 实际 RS485 连接、CRC 有效的反向数据、部分 `0x81` 后的匹配 `0x01` 载荷 | 其他湿腾主机通用；每个组合及机械效果都已验证 |
| 主机型号 | 尚未确认 | 不能用面板型号代替主机型号 |
| 其他面板、OEM 控制器、不同批次 | 尚无兼容性测试 | 外观、品牌或同为 RS485 就可通用 |
| ESPHome / C++ | 尚未提供实现 | 本库已是可直接使用的 ESPHome 组件 |

已有公开 OEM 资料中提到的 Modbus 支持，不能独立证明这条私有 `7E` 链路的格式或字段。
本项目不是厂商授权规格，也不把其他接口的寄存器表合并为本协议事实。

## 如何表达验证程度

| 等级 | 足够支持的描述 | 所需证据 |
| --- | --- | --- |
| 字节层 | “此帧通过长度、CRC 和结束字节检查” | 可重复的原始短帧与算法测试 |
| 操作对照 | “此原厂面板操作对应这些载荷变化” | 明确基态、单一操作、面板显示结果、完整前后帧 |
| 协议响应 | “发送之后观察到匹配反向帧” | 方向、时序、会话边界和完整载荷；排除已知本地回显 |
| 实机效果 | “这台主机在这个条件下产生了请求的变化” | 独立观察或测量，并说明模式及前置状态 |
| 跨设备兼容 | “另一明确型号/版本也通过这些测试” | 第二台设备的型号/版本及对应验证记录 |

同一来源经屏幕、桥接器、MQTT 和仪表盘显示多次，仍是一份底层证据。
重复发送六帧也仍可能只来自一次按钮操作。

## 未解决的问题

- 目标状态与主机实际运行状态是否总是一致；通用 ACK、事务关联和故障状态如何表示。
- `0x20` 周期帧与所有主机回复的对应关系、允许的周期、超时及重试策略。
- 模式切换的完整过渡时序、自动模式下的风速策略、不透明位和尾字节的含义。
- 湿度协议的合法全范围、步长、断电持久化，以及 `0xC4` 的可靠确认方式。
- 温度、湿度、PM2.5 候选类型的物理来源、缩放、符号、量程；室外和盘管字段。
- 风速停止档、第四档、其他控制组合及其他设备固件。

30..90 的湿度限制和 512 字节帧上限属于库策略，不能写进兼容表作为厂商保证。

## 接入另一台设备的最小验证

1. 先确认准确的面板、主机型号及可读到的固件版本；序列号可以省略，不上传标签照片。
2. 核对该设备标识和适配器的电气接口，再做被动监听。RS485、TTL UART 和 USB 不是
   可按引脚位置互换的接口；此库不提供通用接线图或内部供电改造指导。
3. 保存短时、带方向或明确拓扑说明的原始字节；记录波特率和校验参数。
   读取块边界不能当成线上帧边界，开始时的残留半帧要单独处理。
4. 在设备允许的条件下，用原厂面板一次改变一个设置，记录原状态、操作、显示结果和
   后续稳定帧。模式切换需等待过渡结束，不能只取首帧。
5. 只有在已确认的状态与范围内再考虑主动发送，并明确关闭或协调其他主动发送者。
   写入成功、匹配回包和实机效果分别记录，不以一项替代其他项。

提交新兼容信息时，使用 [贡献指南](../CONTRIBUTING.md) 的脱敏格式。
未知设备默认保持“未验证”，实验性遥测必须由使用者显式启用并在界面保留标识。
